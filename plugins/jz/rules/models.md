# Model tiers

- Coordinating a multi-phase program, or a session that starts other sessions: fable.
- Reviewing a change, verifying a branch independently, or a large or cross-cutting task: opus.
- Implementing a scoped unit with named files and a done condition: sonnet, effort medium.
- Scanning files, running a declared script and reporting its output, or a lookup: haiku.
- Pick the tier by the job, never by the model the current session runs on, and name the tier in the brief.
- Raise one tier for a subtle or security-sensitive change. Never run a reviewer below opus.
- A second opinion on a contested design runs on a different model family, through Codex where its plugin is present.
